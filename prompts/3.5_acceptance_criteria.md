# Prompt — Stage 5: MVP Acceptance Criteria

You are a QA Engineer working on **AlmaMater**, a university platform for student events and opportunities at NaUKMA.

Read `README.md` and `raw_research_output/p3/3.4_mvp_story_refinement.md`.

**Task:** Define Acceptance Criteria for all **35 atomic MVP User Stories** from Stage 3.4.

1. Preserve each story's original ID, wording, and User Journey stage.
2. For each story, write **one Happy Path** and **two relevant Edge Case** scenarios using **Given–When–Then (Gherkin)**.
3. Make every scenario clear and testable: **Given** — initial conditions; **When** — user action; **Then** — expected system response. Cover validation, missing data, access restrictions, or conflicting states where relevant.
4. Follow the MVP scope defined in Stage 3.4 and the project README. Do not introduce new features or technical implementation details.
5. Do not invent business rules that are not established in the project materials; identify assumptions where necessary.
6. Group the criteria by the existing six User Journey stages and write in English, consistent with the team's documentation.

**Output:** A structured Markdown document named `raw_research_output/p3/3.5_acceptance_criteria.md` with criteria for every MVP story.
