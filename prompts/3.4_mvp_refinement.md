# Prompt used — Stage 4: MVP User Story Refinement

You are an experienced Product Manager and Agile Business Analyst working on **AlmaMater**, a university event and opportunity discovery platform for NaUKMA.

Read the attached project README, `3.1_user_journey.md`, `3.2_user_story_mapping.md`, and `3.3_story_mapping_scope.md` carefully. Preserve the project terminology and the six journey stages. Use the original story IDs (US-01–US-54) for traceability.

**Task:** Perform Stage 4, "Refine and decompose MVP user stories".

1. Identify only stories explicitly marked **In Scope (MVP)** in the provided scope decision. If the file contains only a prompt or an unclassified story pool, clearly state that no approved scope selection was provided, and propose a defensible minimal MVP slice using the README's agreed constraints. Never present a proposed selection as an approved decision.
2. Check each selected story against the canonical formula: **As a [role], I want [one action], so that [concrete value].** Rewrite as needed without losing its intent.
3. Check atomicity: if a story combines independent user actions, decompose it into separate stories. Preserve traceability with IDs such as US-12a, US-12b. Do not split one coherent action merely because it involves multiple display fields or alternative choices.
4. Keep the core end-to-end workflow functional: university sign-in and organisation authorisation, creation of a structured event, choice of Google Form / direct contact / open attendance, validation and publication, discoverability, student evaluation, and onward participation.
5. Respect the README's MVP limitations. Do not introduce internal registration, chat, recommendations, or automatic social posting merely because these appear in earlier brainstorming or aspirational journey descriptions. Explicitly explain any relevant discrepancy.
6. Produce a concise Markdown report with: scope assumption, selected original stories grouped by journey stage, refined atomic stories (ID, source, canonical user story), decomposition log, and MVP completion check. Do not add story points, implementation tasks, or detailed acceptance criteria.
7. Write in English to match the supplied project documentation. Save the result as `3.4_mvp_story_refinement.md` and save this prompt separately as `3.4_mvp_refinement_prompt.md`.
