# Practice 4.4 — Prompt for the AlmaMater Agent Harness (DOX + docs indexing, Makefile)

**Purpose:** Preserve the compacted prompt used to connect the DOX `AGENTS.md` hierarchy with the project docs and to fix `make` as the single entry point for executive commands.  
**Date:** 2026-10-28  
**Model:** Claude Opus 5.5 (Claude Code)  
**Target artifacts:** `AGENTS.md`, `docs/AGENTS.md`, `docs/commands.md`.

## Prompt

> Act as the coding agent for the AlmaMater repository. The repo uses the **DOX framework**: root `AGENTS.md` is the binding contract, child `AGENTS.md` files own their subtrees, and each one follows the section order Purpose, Ownership, Local Contracts, Work Guidance, Verification, Child DOX Index. Root `CLAUDE.md` only points to `AGENTS.md`. There is **no application code yet**. The repo holds only documentation, an empty `Makefile`, `prompts/` and `raw_research_output/`. **Edit documentation only. Do not commit.**
>
> **Read before editing:** root `AGENTS.md`, `README.md`, `docs/requirements.md`, `docs/api-contracts.md`, `docs/database-schema.md`, `docs/analysis/requirements-digest.md`, `docs/user-stories/README.md`, and `raw_research_output/adr/006-local-runtime-and-scope.md`. List the rest of `docs/`, `prompts/` and `raw_research_output/` so you can index them, but don't read every user story.
>
> **Task 1 — Combine DOX with docs (hybrid indexing).**
>
> 1. Create `docs/AGENTS.md` as the single contract for all of `docs/`, including `user-stories/` and `analysis/`, with no nested `AGENTS.md`. Ownership must say that ADRs are **not** owned here; they live in `raw_research_output/adr/`. Local Contracts must include:
>    - **When to read docs/:** read `docs/` when the user's question requires extensive knowledge of the project as a whole, including the business perspective (product goals, personas, scope, journey, why a feature exists). Also read the docs before creating or changing a FastAPI route, a Pydantic schema, a SQLAlchemy model or migration, or frontend code that calls the API. Open only the user stories the task references.
>    - **Routing table:** MVP scope → `requirements.md` §3; one feature or its acceptance criteria → the matching `user-stories/us-XX-*.md`; open questions and product-owner decisions → `analysis/requirements-digest.md`; routes, DTOs, validation, errors, auth/CSRF → `api-contracts.md`; tables, constraints, migrations, lifecycle → `database-schema.md`; servers, Docker, migrations, tests → `commands.md`.
>    - **Precedence:** user-story file > `requirements.md` > digest decisions > `api-contracts.md` / `database-schema.md`. Contracts follow the requirements. Report conflicts to the user instead of silently picking a side.
>    - **Maintenance:**
>      - one file per story
>      - stable story IDs; the index tables change only when a story's scope, ID, journey step or file name changes
>      - scope changes get a dated "Scope changes of …" entry
>      - `api-contracts.md` and `database-schema.md` are a pair that changes together
>      - `camelCase` for API JSON, `snake_case` for DB columns, and the error envelope from `api-contracts.md` §7
>      - never invent seed data (topics, faculties, organisations, organiser emails)
>    - **Work Guidance and Verification:** leave both empty, because no standards or checks exist yet.
>    - **Child DOX Index:** a one-line description of each owned file and folder.
> 2. In root `AGENTS.md`, add a **Project Docs** section before the Child DOX Index:
>    - `docs/` is the source of truth, and its rules live in `docs/AGENTS.md`
>    - the same "extensive whole-project / business knowledge" trigger
>    - read the docs before API, schema, model, migration or frontend-API work
>    - technology decisions are in `raw_research_output/adr/`
>    - the rest of `raw_research_output/` and `prompts/` are historical inputs, read only on request or when a doc links to them
>
>    Don't duplicate the routing table in root.
> 3. Replace the root placeholder "This project is not yet indexed…" with a real **Child DOX Index**. List `docs/AGENTS.md` first, then the items root owns with no child doc:
>    - `README.md`
>    - `CLAUDE.md`
>    - `Makefile`
>    - `raw_research_output/adr/` (ADR-001…007)
>    - `raw_research_output/p2/` and `p3/`
>    - `prompts/`
>
>    Don't create `AGENTS.md` files for `prompts/` or `raw_research_output/`. They are static historical inputs without their own rules.
>
> **Task 2 — `make` as the single entry point for executive commands.**
>
> 1. Create `docs/commands.md` with:
>    - **§1 Rule:**
>      - run all executive commands (servers, Docker, migrations, tests, linters, formatters, DB resets) via `make <target>` instead of calling `docker compose`, `uvicorn`, `alembic`, `npm` or `pytest` directly
>      - if a target is missing, add it to the `Makefile` first
>      - keep the target table in sync with the `Makefile`
>      - give destructive targets explicit names and run them only after explicit user confirmation
>      - include a one-line "why"
>    - **§2 Makefile conventions:**
>      - every target in `.PHONY`
>      - `help` as the default goal, built from `## description` comments
>      - `COMPOSE := docker compose`
>      - container commands via `$(COMPOSE) exec` or `$(COMPOSE) run --rm`, with no host toolchain (per ADR-006)
>      - arguments as variables (`name=`, `args=`)
>      - short recipes, with complex logic moved into scripts
>    - **§3 Targets:**
>      - state that the `Makefile` is empty and there is no `compose.yaml` yet
>      - list the planned targets derived from the ADR-006 services (`frontend`, `backend`, `db`, `migrate`, `worker`), each with status `planned`: `help`, `up`, `down`, `restart`, `logs`, `ps`, `backend-shell`, `migrate`, `migration`, `test`, `lint`, `format`, `db-shell`, `db-reset` (mark it destructive)
>
>    **Do not populate the `Makefile`** and do not claim any command works.
> 2. Do a DOX pass:
>    - add the `commands.md` row to the routing table and the Child DOX Index in `docs/AGENTS.md`
>    - add a repo-wide User Preferences rule to root `AGENTS.md`: run executive commands only via `make`, add a missing target first, and see `docs/commands.md`
>    - list the `Makefile` in the root Child DOX Index
>
> **Report back:** the changed files and what each now contains, any docs intentionally left unchanged and why, and the doc conflicts you noticed but did not fix. The known conflicts are:
> 1. US-45a–c notifications are in scope in `requirements.md` and ADR-007, but both contracts exclude them.
> 2. `durationMinutes` is optional per digest D-01 but required in the contracts.
> 3. Digest D-xx IDs collide with the schema's D-01–D-08.

> 5. The US-50a–d multi-select and date-range filters don't match the single-value `GET /api/events` parameters.
