# Frontend Iteration 1 — Event Catalog and Creation Form Shell

Implement frontend iteration 1 for the AlmaMater event creation epic.

Before editing, read the complete applicable instruction chain:

- `AGENTS.md`
- `frontend/AGENTS.md`
- `docs/AGENTS.md`
- relevant sections of `docs/api-contracts.md`
- relevant user stories: US-07, US-39, and US-49

Use `origin/backend/events` as the functional base and work in a dedicated feature branch, such as `feature/event-create-catalog`.

## Scope

1. Add frontend routes:
   - `/events` — event catalog
   - `/events/new` — event creation form shell
2. Make `/events` the default application destination.
3. Add navigation actions for “Events” and “Create event”.
4. On `/events`:
   - call `GET /api/events` through the Vite `/api` proxy;
   - display event cards with title, start date/time, organization name, and format;
   - do not add event-detail links;
   - handle loading, empty, and error states.
5. On `/events/new`:
   - create the initial form shell;
   - load organizations from `GET /api/organizations`;
   - load topics from `GET /api/topics`;
   - load faculties from `GET /api/faculties`;
   - display organization, topic, and faculty select inputs;
   - handle loading and error states;
   - do not submit the form in this iteration.
6. Keep API requests in dedicated frontend API modules.
7. Keep the implementation small and consistent with the existing React + Vite JavaScript project.

## Out of scope

- authentication and authorization;
- event detail pages;
- catalog filters;
- event submission and validation;
- editing or cancellation;
- backend business-logic changes;
- invented seed or reference data.

Run executive commands only through root Makefile targets. If a required frontend verification target is missing, add it to the Makefile and document it in `docs/commands.md`.

- report changed files, verification results, and remaining work for iteration 2;
