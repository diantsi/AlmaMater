Act as a QA Automation Engineer. Analyze the current AlmaMater repository, focusing on:

- `docs/user-stories/` — user stories and acceptance criteria.
- `docs/testing-strategy.md` — testing strategy and conventions.
- `docs/api-contracts.md` — expected API behaviour.
- Existing source code, automated tests, and test configuration.

## Objective

Implement automated tests for 5–6 critical user stories from `docs/user-stories/`. Review existing test coverage before selecting stories to avoid duplication. Prioritize uncovered scenarios according to the testing strategy and cover different functional areas and testing levels.

## Requirements

- Base tests on documented acceptance criteria (Given-When-Then scenarios or requirement checklists). Reference the original user story IDs.
- Cover all relevant acceptance criteria, including Happy Paths and Edge Cases: validation errors, forbidden actions, boundary conditions, and invalid state transitions.
- Follow the existing testing strategy, frameworks, directory structure, and naming conventions.
- Reuse existing fixtures and factories. Ensure test data isolation and cleanup.
- Test actual application behaviour, not mocked business logic. Mock external services only where necessary.
- Verify test quality through intentional code mutation. For each selected user story:
  1. Confirm that the original tests pass.
  2. Temporarily break a relevant business condition.
  3. Run the corresponding tests and confirm that they fail for the expected reason.
  4. Restore the original code and confirm that the tests pass again.
- Ensure all automated tests can be executed with a single terminal command. Reuse or extend the existing Makefile targets as appropriate.
- Preserve existing functionality, tests, and user changes. Do not introduce unrelated changes or weaken assertions to make tests pass.

## Deliverables

1. Implemented and configured automated tests.
2. A concise report in `docs/testing-report.md` containing:
   - Selected user story IDs and reasons for their selection.
   - Acceptance criteria and corresponding test cases.
   - Covered Happy Paths and Edge Cases.
   - Intentional code mutations and actual fail/pass results.
   - Test execution command and final test results.
   - Remaining coverage gaps or blockers.
3. Save this exact prompt in `docs/test-generation-prompt.md`.

Run the complete automated test suite before finishing. Verify that all temporary mutations have been reverted. Report actual results without fabricating successful executions.

Prioritize meaningful assertions, reliability, and maintainability over the total number of tests.
