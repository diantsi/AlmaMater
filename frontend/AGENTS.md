# frontend/ — React + Vite client

## Purpose

- Responsive browser client in React + Vite + JavaScript (ADR-002)
- Current state: frontend iterations 1–8 of `prompts/5.5_frontend_iterations_plan.md` (US-01, US-02, US-03, US-07, US-12a/b/c, US-13, US-15a/b, US-16a/b, US-17a/b/c, US-21, US-25, US-26, US-36, US-39, US-41, US-43, US-44a/b, US-45a, US-47, US-49, US-50a/b/c/d, US-51, US-52a/b/c, US-55a/b): sign-in and members-only access, `/events` catalog with filters and organisation dashboard, `/events/new` form publishing every §5.1 field with a publication confirmation, `/events/:eventId` details page with edit and cancel for the owning organisation and an email-updates subscription toggle, `/events/:eventId/edit`
- Visual design: every page reproduces the AlmaMater HTML references (`landing.html`, `events.html`, `almamater-sign-in-pass.html`, `event-details.html`, `create-event.html`, `edit-event.html`, `organisation-dashboard.html`, kept outside the repo) with Ukrainian copy; the publication confirmation, subscription panel, page notices and organiser actions on the details page have no reference and use the same design system

## Ownership

- Owns everything under `frontend/`: `src/`, `index.html`, `vite.config.js`, `eslint.config.js`, `jsconfig.json`, `package.json`, `package-lock.json`, `Dockerfile`
- API shapes are owned by `docs/api-contracts.md`; this folder consumes them

## Local Contracts

- Layout (ADR-001): `src/main.jsx` (entry, `BrowserRouter`), `src/App.jsx` (anonymous `LandingPage` and `SignInPage`; member layout `MemberHeader` / `main#main.page` / `Footer` + routes), `src/pages/` (one component per route), `src/components/` (reusable UI), `src/api/` (one module per API area), `src/lib/` (framework-free helpers), `src/assets/` (static images), plain CSS in `src/index.css`
- Design system (`src/index.css`): colour, font, grain and `--wrap` width tokens on `:root`; Dela Gothic One (headings, wordmark) and Manrope (body) from Google Fonts in `index.html`; paper background `assets/paper.jpg` plus the fixed grain overlay; shared `.button`, `.button--nav`, `.status`, `.hint`. `index.html` holds the SVG sprite (`#brand`, `#arrow`, `#paper-clip`, `#frame-star`, `#paper-outline`) that components draw with `<svg><use href="#id" /></svg>`; other drawings (poster art, filter and meta icons) stay inline in their component. `#root` is a full-height flex column (footer at the bottom); `.page` is the `--wrap` column and each page root sets its own padding (`.catalog`, `.detail-page`, `.create-page` max 1120px, `.org-dashboard`, `.page-section`)
- Shell components: `Logo` (star mark + "almamater" wordmark, links to `/`), `PaperFrame` (hand-drawn outline, paper clip, optional star), `Header` (skip link, logo and the given navigation in the frame: centred `.nav-links` and a right `.nav-end`, or one row with `simple`), `MemberHeader` (`NavLink`s "Афіша" and, only when `canPublish`, "Мої події", which move to a second row below 780px; account badge with avatar, login and domain, text hidden below 1150px; "Вийти" button; owns the logout call and its error), `Footer` (logo and NaUKMA name, no links), `PageNotice` (back link + dashed card for loading, not-found, no-access and error states), `ManageActions` ("Редагувати" link to `<eventUrl>/edit` and "Скасувати" button, used on the details page and the dashboard)
- Routes (React Router, ADR-002): `/` → `LandingPage` (anonymous, static, no event data; header "Афіша" + "Створити подію", ticker with a pause button that also pauses the page animations, route doodle drawn once scrolled into view), `/login` and `/sign-in` → `SignInPage` (anonymous; rendered outside `AuthProvider`; `/login` is where signed-out visitors land, `/sign-in` is the backend's failure redirect). Every other route is wrapped in `AuthProvider`: `/events` → `EventsPage` (catalog, default destination), `/events/new` → `CreateEventPage`, `/events/:eventId` → `EventDetailsPage` (the §5.2 `eventUrl`), `/events/:eventId/edit` → `EditEventPage`, `/organisation` → `OrganisationPage`; every other path redirects to `/events`
- Auth (api-contracts.md §2, §4): `components/AuthProvider.jsx` loads `GET /api/auth/me` once and renders children only for a member (loading / error-with-retry states otherwise); `useAuth()` returns `{ user: { id, email }, organization, canPublish, csrfToken }`. New pages read it via `useAuth()` and never add their own sign-in logic
- `401 NOT_AUTHENTICATED` from any API call: `api/http.js` navigates to `/login?returnTo=<path + query>` and leaves the promise pending, so no event content or error flashes (US-55b). `SignInPage`'s "Увійти через Office 365" link goes to `/api/auth/login?returnTo=<returnTo>` (`signInUrl`). The backend redirects failed sign-ins to `/sign-in?error=AUTHENTICATION_FAILED|UNIVERSITY_ACCOUNT_REQUIRED`; `SignInPage` maps the code to a message (unknown codes → the `AUTHENTICATION_FAILED` text)
- Publishing rights: the "Мої події" link, the organisation line under the catalog heading and the "Створити подію" button (US-02; `components/Organizer.jsx`: `OrganizationName` and the lime `CreateEventButton`, shared with the dashboard) and `/organisation` only when `canPublish`; `/events/new` and `/organisation` without it show a no-access notice (US-07 AC2). The backend still enforces this
- API modules: `api/http.js` (`getJson`, `postJson(path, body, expectedStatus?)`, `patchJson(path, body)`, `putJson(path, expectedStatus?)` (no body), `deleteJson(path, expectedStatus?)` (any other `2xx` than `expectedStatus` rejects with a plain `Error`) + `ApiError` carrying `status`/`code`/`details` from the `api-contracts.md` §7 envelope; adds `X-CSRF-Token` set by `setCsrfToken` to every non-GET request; `204` resolves to `null`), `api/auth.js` (`fetchMe` → `GET /api/auth/me`, `logout` → `POST /api/auth/logout`), `api/events.js` (`fetchEvents` → `GET /api/events` `items`, `fetchEvent(id)` → `GET /api/events/{id}`, `createEvent` → `POST /api/events`, resolving only on `201`; `updateEvent(id, patch)` → `PATCH /api/events/{id}`; `cancelEvent(id)` → `POST /api/events/{id}/cancel`, resolving only on `200`; `subscribe(id)` → `PUT /api/events/{id}/subscription`, resolving only on `200`; `unsubscribe(id)` → `DELETE /api/events/{id}/subscription`, resolving only on `204`), `api/organizations.js` (`GET /api/organizations`, catalog filter options), `api/dictionaries.js` (`GET /api/topics`, `GET /api/faculties`). All `fetch` calls live in `src/api/`; pages never call `fetch` directly
- Helpers: `lib/kyivTime.js` (all event times are entered and shown as `Europe/Kyiv` wall time; `kyivLocalToIso` turns a `datetime-local` value into RFC 3339 with the Kyiv offset and returns `null` for a wall time Kyiv never shows (skipped spring DST hour, calendar overflow such as Feb 29 of a common year, hour 25, minute 60); the repeated autumn hour resolves to its later (winter-time) occurrence; `isoToKyivLocal` the reverse, to the minute; `kyivDateParts` gives day/month/year/time for date stamps, `MONTHS_SHORT`, `formatKyivDateTime` → "18 лютого 2027, 18:00"), `lib/eventOptions.js` (`format` / `participationMethod` enum values with form labels, `FORMAT_TAGS` "Онлайн" / "Очно" for tickets, `participationMethodLabel`, `NEWCOMERS_OPTIONS` select options, `eventCount` with Ukrainian plurals), `lib/eventForm.js` (event-form fields, labels, `OPTIONAL_FIELDS`, conditional-field maps, validation, `buildPayload` for create, `valuesFromEvent` / `buildPatch` for edit, `submissionErrors` API error mapping), `lib/catalogFilters.js` (filter keys, URL query ↔ filter state, `filtersToParams`, `countActiveFilters`, `hasActiveFilters`)
- `EventsPage`: the URL query owns the filters (api-contracts.md §6.1); loading, error, empty, no-results, invalid-date and malformed-link states; result count via `eventCount` in the shared `.count` pencil-ring label, right above the cards (as on the dashboard); below 650px `CatalogFilters` collapses behind a "Фільтри (n)" toggle (`open` prop).
- `CatalogFilters`: checkbox groups for topic, faculty and organisation (options from the dictionary APIs), Kyiv start-date range with server `dateTo` errors under "До", "Очистити фільтри"; the heading takes focus after clearing
- `EventCard`: ticket with a coloured poster: the colour comes from `ticketStyle(event.id)` (stable hash of the event id over the palette lime / yellow / pink / blue, white date ink on blue), the sticker from `topicArt(topicCode)` (keyword match on the stable topic `code`, e.g. science → laptop, career → CV, art → film; unknown topics → neutral ticket); catalog and dashboard get codes from `useTopicCodes()` (`GET /api/topics`), the details ticket uses the same two functions, Kyiv date stamp, time, organisation name and `FormatTag`; in the catalog the whole card is one click target (the title `Link` to `eventUrl` is stretched over the card with CSS `::after`, so there is a single link per card). With `children` (dashboard) it shows an "Опубліковано" tag and the given actions instead of the organisation name and arrow, and the link is not stretched
- `EventDetailsPage`: loads the event, topics and faculties in parallel; ticket in the topic's poster colour (topic and format tags, title, organiser, date stamp with the poster art), "Про подію", "Деталі події" list (start, duration, venue or meeting link, speaker, faculty, audience, newcomers, method; `null` optionals hidden), and a right column with organiser actions, "Як долучитися", "Сповіщення" and "Поділитися" (absolute `eventUrl`); states via `PageNotice`: loading, `404 EVENT_NOT_FOUND` / `400 MALFORMED_REQUEST` → not-found, other errors; a cancelled (`status: CANCELLED`) or past (`startsAt <= now`) event shows a banner, a closed note in "Як долучитися" and the meeting URL as plain text; a success notice is shown from the navigation state (`{ notice }`) after a save and after a cancellation
- Edit and cancel (US-44a, US-44b, api-contracts.md §5.2, §6.4, §6.5): `EventDetailsPage` shows `ManageActions` only when `canManage` and the event is neither cancelled nor past; the backend still enforces ownership
- `EditEventPage`: loads the event, topics and faculties; not-found for `404` / `400`; no-access message when not `canManage`; closed message for cancelled or past events; otherwise `EventForm` prefilled by `valuesFromEvent`; back and "Скасувати" lead to `/organisation`. Save sends `PATCH` with the loaded `revision` and only changed fields (`buildPatch`: emptied optionals and fields made irrelevant by a format / method change are `null`); no change → form-level "not changed" message, no request. `200` → navigates to `eventUrl` with a "Зміни збережено." notice. `409 EVENT_REVISION_CONFLICT` → form-level message plus "Завантажити актуальну версію" (refetches and resets the form), `409 EVENT_NOT_EDITABLE`, `403 ORGANIZATION_ACCESS_DENIED`, `404` → form-level messages; `422` maps like create
- Cancel: `CancelEventDialog` (native modal `<dialog>` in the dashboard reference design, "Залишити" focused first, Escape closes unless pending) sends `cancelEvent` itself; `200` → `onCancelled({ status, revision, cancelledAt })` (details merges it so the cancelled banner appears at once; the dashboard drops the card); `409 EVENT_ALREADY_CANCELLED` / `EVENT_NOT_EDITABLE` → `onConflict(message)` (the parent shows it and reloads); other errors stay in the dialog
- `SubscriptionSection` (US-45a, api-contracts.md §5.2 `subscribed`, §6.6, §6.7): rendered by `EventDetailsPage` below "Як долучитися" as its own "Сповіщення" panel, only for upcoming non-cancelled events; text says emails go to the university address and that it does not register attendance; one button "Повідомляти про зміни" / "Вимкнути сповіщення", disabled ("Зберігаємо…") and ref-guarded while pending; success updates `event.subscribed` in place (a reload reads it from `GET /api/events/{id}`); `409 EVENT_NOT_SUBSCRIBABLE` → page notice and event reload (the section disappears); other errors show inside the section
- `ParticipationSection` (api-contracts.md §5.3): "Як долучитися" panel; `GOOGLE_FORM` → external "Відкрити Google Form" link (`target="_blank"`, `rel="noopener noreferrer"`), `DIRECT_CONTACT` → `contactDetails` as written, `OPEN_ATTENDANCE` → `attendanceInstructions`, the registration deadline when set; with `closedReason` only that reason; never wording that implies in-app registration
- `EventForm` (shared by create and edit) renders every §5.1 field in four numbered panels (01 "Про подію": title with a length counter, description, start, speaker, duration; 02 "Тема та факультет": topic, faculty, audience, newcomers; 03 "Формат і місце": format, venue / meeting link; 04 "Участь": method, its field, registration deadline), runs the client checks, keeps the values and focuses `ErrorSummary` on failure; "Скасувати" links to `cancelTo`; the page's `onSubmit(values)` resolves `null` on success or `{ fieldErrors, formErrors }`. `EventFormHeading` (back link, heading with the pencil sticker, publisher line, required-fields note) is shared by both pages. The reference's ticket-colour panel is not built: the API has no colour field
- `CreateEventPage`: loads topics and faculties in parallel (loading/error states), shows "Публікуєте від імені <organisation>" and renders `EventForm` with every §5.1 field (no organisation field; the server assigns it, US-03); back and "Скасувати" lead to `/events`
- Conditional fields: only the field of the selected format / method is shown, validated and sent; switching clears the inactive fields' values and errors (`withField`)
- Form rules: required fields are marked `*` with the `required` attribute; the `OPTIONAL_FIELDS` (`speakerName`, `intendedAudience`, `newcomersWelcome`, `durationMinutes`, `registrationDeadline`) are always shown, labelled "(optional)" and never required (US-13). Client checks are limited to required values, complete `https://` links (the raw text must start with `https://` and a host, contain no whitespace or backslash, and parse with `new URL`, because the raw text is what gets sent), start and deadline that exist as Kyiv wall time (`datetime-local`), duration as a whole number > 0 (text input, `inputMode="numeric"`) and deadline not after start; title/speaker/venue `maxLength` 160/160/500. The server stays authoritative (e.g. future start)
- `newcomersWelcome` is a "Не зазначено" / "Так" / "Ні" select (`''` / `'true'` / `'false'`); "Не зазначено" is preselected and omitted, never defaulted
- Submit: `buildPayload` sends trimmed active fields only and leaves out empty optionals (date-times → RFC 3339 with Kyiv offset, duration → number, newcomers → boolean); the button is disabled and a ref blocks re-entry while pending. Only a `201` (`createEvent` rejects any other status) replaces the form with `PublicationConfirmation` (US-41, US-43): focused "Подію опубліковано" heading, "Переглянути подію" link to `eventUrl`, the absolute share URL in a read-only input with "Скопіювати" (Clipboard API; on failure a hint asks to copy by hand), "До афіші" and "Створити ще одну подію" (empty form). Errors keep all values: `details[].field` matching a shown field appears under that input, every other detail and detail-less failures (`500`, network) appear as form-level messages; `ErrorSummary` lists all issues, links to inputs and takes focus
- Form components: `EventForm`, `Field` (`.form-field`: label with required or "(необов’язково)" mark, control, hint, errors, `aria-invalid`/`aria-describedby` via render prop), `TextField` (`counter`; `datetime-local` gets the calendar decoration), `SelectField` (the one custom dropdown from the references: combobox button + listbox, arrow/Home/End/Enter/Space/Escape/Tab and type-ahead, closes on outside click, `aria-invalid` from the field errors; `placeholder` adds an empty first option, disabled "Поки немає варіантів" when the list is empty), `RadioGroup` (fieldset of paper choice cards), `ErrorSummary` (`.form-message` with links to the fields); form styles are scoped to `.create-page`, so the catalog date fields keep their own look
- `SignInPage`: "Твоя перепустка в AlmaMater" ticket with the door illustration; error codes map to Ukrainian messages (unknown codes → the `AUTHENTICATION_FAILED` text); simple header with "На головну"
- `OrganisationPage` (`/organisation`, US-02): "Мої події", organisation name, "Створити подію" and the organisation's upcoming published events from the catalog query `GET /api/events?organizationId=<own id>` as `EventCard`s with `ManageActions`; cancelling removes the card and shows a fixed note; no list of cancelled or past events (the API has none: api-contracts.md says there is no list of the organisation's events); empty, loading and error states
- Pages that fetch on mount ignore late responses after unmount (StrictMode runs effects twice)
- The browser only calls same-origin relative `/api/...` URLs; the Vite dev server proxies `/api` to `API_PROXY_TARGET` (`http://backend:8000` in Compose). Never hard-code backend hosts
- Dependencies are pinned exactly; change them in `package.json`, then run `make frontend-lock` and commit the lockfile
- Code quality: `eslint.config.js` configures ESLint for JavaScript and React; `jsconfig.json` enables TypeScript checking with `allowJs`, `checkJs` and `noEmit`. Use JSDoc for explicit component prop and state types without converting the frontend to TypeScript
- Runs only inside Compose (`frontend` service, port `FRONTEND_PORT`, default 5173) via `make` targets; the source is bind-mounted and `node_modules` lives in a container volume

## Work Guidance

- Restyle pages by reproducing the HTML design references exactly (colours, fonts, sizes, spacing, texture, borders, shadows, animations, original SVG art); they win over generic design advice. Do not swap in stock outline icons or add decorations the reference lacks
- References are design only: never copy their demo data, test emails or fake API; keep auth, roles, CSRF, routes, API calls and filters unchanged
- Reuse and restyle existing components; shared values go into the CSS tokens; no new dependencies

- `make frontend-typecheck` runs TypeScript static checking on `src/` without generating output files
