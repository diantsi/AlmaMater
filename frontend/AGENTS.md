# frontend/ — React + Vite client

## Purpose

- Responsive browser client in React + Vite + JavaScript (ADR-002)
- Current state: frontend iterations 1–8 of `prompts/5.5_frontend_iterations_plan.md` (US-01, US-02, US-03, US-07, US-12a/b/c, US-13, US-15a/b, US-16a/b, US-17a/b/c, US-21, US-25, US-26, US-36, US-39, US-41, US-43, US-44a/b, US-45a, US-47, US-49, US-50a/b/c/d, US-51, US-52a/b/c, US-55a/b): sign-in and members-only access, `/events` catalog with filters and organisation dashboard, `/events/new` form publishing every §5.1 field with a publication confirmation, `/events/:eventId` details page with edit and cancel for the owning organisation and an email-updates subscription toggle, `/events/:eventId/edit`

## Ownership

- Owns everything under `frontend/`: `src/`, `index.html`, `vite.config.js`, `eslint.config.js`, `jsconfig.json`, `package.json`, `package-lock.json`, `Dockerfile`
- API shapes are owned by `docs/api-contracts.md`; this folder consumes them

## Local Contracts

- Layout (ADR-001): `src/main.jsx` (entry, `BrowserRouter`), `src/App.jsx` (header nav + routes), `src/pages/` (one component per route), `src/components/` (reusable UI), `src/api/` (one module per API area), `src/lib/` (framework-free helpers), plain CSS in `src/index.css`
- Routes (React Router, ADR-002): `/login` and `/sign-in` → `SignInPage` (anonymous; rendered outside `AuthProvider`; `/login` is where signed-out visitors land, `/sign-in` is the backend's failure redirect). Every other route is wrapped in `AuthProvider`: `/events` → `EventsPage` (catalog, default destination), `/events/new` → `CreateEventPage`, `/events/:eventId` → `EventDetailsPage` (the §5.2 `eventUrl`), `/events/:eventId/edit` → `EditEventPage`; every other path, including `/`, redirects to `/events`. Header: `NavLink`s "Events" and, only when `canPublish`, "Create event"; the signed-in email and a "Log out" button (`POST /api/auth/logout`, then full navigation to `/login`)
- Auth (api-contracts.md §2, §4): `components/AuthProvider.jsx` loads `GET /api/auth/me` once and renders children only for a member (loading / error-with-retry states otherwise); `useAuth()` returns `{ user: { id, email }, organization, canPublish, csrfToken }`. New pages read it via `useAuth()` and never add their own sign-in logic
- `401 NOT_AUTHENTICATED` from any API call: `api/http.js` navigates to `/login?returnTo=<path + query>` and leaves the promise pending, so no event content or error flashes (US-55b). `SignInPage`'s "Sign in" link goes to `/api/auth/login?returnTo=<returnTo>` (`signInUrl`). The backend redirects failed sign-ins to `/sign-in?error=AUTHENTICATION_FAILED|UNIVERSITY_ACCOUNT_REQUIRED`; `SignInPage` maps the code to a message (unknown codes → the `AUTHENTICATION_FAILED` text)
- Publishing rights: "Create event" link and the organisation dashboard (organisation name + "Create event" at the top of `EventsPage`, US-02) only when `canPublish`; `/events/new` without `canPublish` shows a no-access message (US-07 AC2). The backend still enforces this
- API modules: `api/http.js` (`getJson`, `postJson(path, body, expectedStatus?)`, `patchJson(path, body)`, `putJson(path, expectedStatus?)` (no body), `deleteJson(path, expectedStatus?)` (any other `2xx` than `expectedStatus` rejects with a plain `Error`) + `ApiError` carrying `status`/`code`/`details` from the `api-contracts.md` §7 envelope; adds `X-CSRF-Token` set by `setCsrfToken` to every non-GET request; `204` resolves to `null`), `api/auth.js` (`fetchMe` → `GET /api/auth/me`, `logout` → `POST /api/auth/logout`), `api/events.js` (`fetchEvents` → `GET /api/events` `items`, `fetchEvent(id)` → `GET /api/events/{id}`, `createEvent` → `POST /api/events`, resolving only on `201`; `updateEvent(id, patch)` → `PATCH /api/events/{id}`; `cancelEvent(id)` → `POST /api/events/{id}/cancel`, resolving only on `200`; `subscribe(id)` → `PUT /api/events/{id}/subscription`, resolving only on `200`; `unsubscribe(id)` → `DELETE /api/events/{id}/subscription`, resolving only on `204`), `api/organizations.js` (`GET /api/organizations`, catalog filter options), `api/dictionaries.js` (`GET /api/topics`, `GET /api/faculties`). All `fetch` calls live in `src/api/`; pages never call `fetch` directly
- Helpers: `lib/kyivTime.js` (all event times are entered and shown as `Europe/Kyiv` wall time; `kyivLocalToIso` turns a `datetime-local` value into RFC 3339 with the Kyiv offset, `isoToKyivLocal` the reverse, to the minute), `lib/eventOptions.js` (`format` / `participationMethod` enum values and labels, `formatLabel`, `participationMethodLabel`, `NEWCOMERS_OPTIONS`), `lib/eventForm.js` (event-form fields, labels, `OPTIONAL_FIELDS`, conditional-field maps, validation, `buildPayload` for create, `valuesFromEvent` / `buildPatch` for edit, `submissionErrors` API error mapping), `lib/catalogFilters.js` (filter keys, URL query ↔ filter state, `filtersToParams`)
- `EventsPage`: `CatalogFilters` panel (multi-select topic, faculty, organisation as checkbox groups; `dateFrom` / `dateTo`; "Clear filters"); filter state lives in the URL query string with the API parameter names (shareable, survives reload) and `fetchEvents(filters)` sends repeated params; loading, error, `422` date errors next to the date inputs, empty catalog vs. "no events match your filters", and list states; `EventCard` shows title, start, organisation name and format label; the whole card is one click target (the title `Link` to `eventUrl` is stretched over the card with CSS `::after`, so there is a single link per card)
- `EventDetailsPage`: loads the event, topics and faculties in parallel; shows every §5.2 field with labels, topic/faculty resolved to names, `null` optionals hidden, Kyiv times; states: loading, `404 EVENT_NOT_FOUND` / `400 MALFORMED_REQUEST` → not-found message, other errors → error message; a cancelled (`status: CANCELLED`) or past (`startsAt <= now`) event shows a banner, a closed participation note instead of the participation route, and the meeting URL as plain text; a "Share" section shows the absolute `eventUrl`; a success notice is shown from the navigation state (`{ notice }`) after a save and after a cancellation
- Edit and cancel (US-44a, US-44b, api-contracts.md §5.2, §6.4, §6.5): `EventDetailsPage` shows "Edit event" (link to `<eventUrl>/edit`) and "Cancel event" only when `canManage` and the event is neither cancelled nor past; the backend still enforces ownership
- `EditEventPage`: loads the event, topics and faculties; not-found for `404` / `400`; no-access message when not `canManage`; closed message for cancelled or past events; otherwise `EventForm` prefilled by `valuesFromEvent`. Save sends `PATCH` with the loaded `revision` and only changed fields (`buildPatch`: emptied optionals and fields made irrelevant by a format / method change are `null`); no change → form-level "not changed" message, no request. `200` → navigates to `eventUrl` with a "Changes saved." notice. `409 EVENT_REVISION_CONFLICT` → form-level message plus "Reload latest version" (refetches and resets the form), `409 EVENT_NOT_EDITABLE`, `403 ORGANIZATION_ACCESS_DENIED`, `404` → form-level messages; `422` maps like create
- Cancel: `CancelEventDialog` (native modal `<dialog>`, "Keep event" focused first, Escape closes unless pending) → `cancelEvent`; `200` merges `status` / `revision` / `cancelledAt` into the shown event, so the cancelled banner appears at once; `409 EVENT_ALREADY_CANCELLED` / `EVENT_NOT_EDITABLE` close the dialog, show a notice and reload the event; other errors stay in the dialog
- `SubscriptionSection` (US-45a, api-contracts.md §5.2 `subscribed`, §6.6, §6.7): rendered by `EventDetailsPage` below `ParticipationSection` as its own "Email updates" section, only for upcoming non-cancelled events; text says emails go to the university address and that it does not register attendance; one button "Email me about changes" / "Stop email updates", disabled ("Saving…") and ref-guarded while pending; success updates `event.subscribed` in place (a reload reads it from `GET /api/events/{id}`); `409 EVENT_NOT_SUBSCRIBABLE` → page notice and event reload (the section disappears); other errors show inside the section
- `ParticipationSection` (api-contracts.md §5.3): `GOOGLE_FORM` → external link (`target="_blank"`, `rel="noopener noreferrer"`), `DIRECT_CONTACT` → `contactDetails` as written, `OPEN_ATTENDANCE` → `attendanceInstructions`; never wording that implies in-app registration
- `EventForm` (shared by create and edit) renders every §5.1 field, runs the client checks, keeps the values and focuses `ErrorSummary` on failure; the page's `onSubmit(values)` resolves `null` on success or `{ fieldErrors, formErrors }`
- `CreateEventPage`: loads topics and faculties in parallel (loading/error states), shows "Publishing as <organisation>" and renders `EventForm` with every §5.1 field (no organisation field; the server assigns it, US-03): title, description, start, optional duration and speaker; topic, faculty, optional intended audience and newcomers welcome; `format` with `venue` / `meetingUrl`; `participationMethod` with `googleFormUrl` / `contactDetails` / `attendanceInstructions`, optional registration deadline
- Conditional fields: only the field of the selected format / method is shown, validated and sent; switching clears the inactive fields' values and errors (`withField`)
- Form rules: required fields are marked `*` with the `required` attribute; the `OPTIONAL_FIELDS` (`speakerName`, `intendedAudience`, `newcomersWelcome`, `durationMinutes`, `registrationDeadline`) are always shown, labelled "(optional)" and never required (US-13). Client checks are limited to required values, `https://` URL syntax, parseable start and deadline (Kyiv `datetime-local`), duration as a whole number > 0 (text input, `inputMode="numeric"`) and deadline not after start; title/speaker/venue `maxLength` 160/160/500. The server stays authoritative (e.g. future start)
- `newcomersWelcome` is a Yes / No / Not specified radio group (`'true'` / `'false'` / `''`); "Not specified" is preselected and omitted, never defaulted
- Submit: `buildPayload` sends trimmed active fields only and leaves out empty optionals (date-times → RFC 3339 with Kyiv offset, duration → number, newcomers → boolean); the button is disabled and a ref blocks re-entry while pending. Only a `201` (`createEvent` rejects any other status) replaces the form with `PublicationConfirmation` (US-41, US-43): focused "Event published" heading, "View event" link to `eventUrl`, the absolute share URL in a read-only input with "Copy link" (Clipboard API; on failure a hint asks to copy by hand), "Go to events" and "Create another event" (empty form). Errors keep all values: `details[].field` matching a shown field appears under that input, every other detail and detail-less failures (`500`, network) appear as form-level messages; `ErrorSummary` lists all issues, links to inputs and takes focus
- Form components: `EventForm`, `Field` (label, required mark, hint, errors, `aria-invalid`/`aria-describedby` via render prop), `TextField`, `SelectField` (disabled with "None available yet" when a list is empty), `RadioGroup` (fieldset/legend), `ErrorSummary`; `Field`, `TextField` and `RadioGroup` take `optional` to show the "(optional)" mark
- Pages that fetch on mount ignore late responses after unmount (StrictMode runs effects twice)
- The browser only calls same-origin relative `/api/...` URLs; the Vite dev server proxies `/api` to `API_PROXY_TARGET` (`http://backend:8000` in Compose). Never hard-code backend hosts
- Dependencies are pinned exactly; change them in `package.json`, then run `make frontend-lock` and commit the lockfile
- Code quality: `eslint.config.js` configures ESLint for JavaScript and React; `jsconfig.json` enables TypeScript checking with `allowJs`, `checkJs` and `noEmit`. Use JSDoc for explicit component prop and state types without converting the frontend to TypeScript
- Runs only inside Compose (`frontend` service, port `FRONTEND_PORT`, default 5173) via `make` targets; the source is bind-mounted and `node_modules` lives in a container volume
